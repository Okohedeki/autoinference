# KV-Cache Management and Long-Context Inference Techniques (catalog, through Oct 2026)

Scope note for the report writer: one bullet = one technique. Each entry uses the fields **What / Slot / Pre (preconditions) / Gain / Quality / Maturity / Src**. "Slot" uses these engine slot names:
`kv-allocator` (block/page layout, memory pool), `prefix-cache` (reuse index and eviction), `kv-dtype` (storage quantization plus quant/dequant kernels), `kv-select` (eviction, pruning, budget policy), `attn-kernel` (decode and prefill attention kernels, sparse attention), `kv-tier` (offload, CPU/disk/remote), `scheduler` (chunked prefill, batching, admission), `pos-enc` (RoPE scaling), `prompt-xform` (prompt compression), `model-arch` (needs retraining or conversion).
Verification level: items marked **[V]** were checked against a primary source this session (Oct 2026). Unmarked pre-2025 entries cite the canonical arXiv/venue page. Their headline numbers are the papers' own abstract claims, recalled and not re-fetched this session, so treat exact figures as approximate. Dates are first-arXiv month unless a venue is given.

## 1. Memory management (paging, prefix reuse, shared-prefix attention, defrag, sliding window, hybrid state)

### Takeaway
Paged block allocation (vLLM PagedAttention) plus a prefix index (radix tree or hash-of-blocks) is the settled baseline. Every engine ships it, and it is required before any eviction, quantization or offload slot can work. On a single 4090 the important current additions are (a) the hybrid allocators that handle sliding-window and linear-attention (Mamba/DeltaNet) layers without wasting full-KV pages, and (b) a host-RAM prefix tier (llama.cpp `--cache-ram`, vLLM OffloadingConnector, SGLang HiCache) for multi-turn reuse.

### Cited Findings
**Paged and virtual-memory allocation**
- **PagedAttention / vLLM** (Sep 2023, SOSP'23). What: fixed-size KV blocks with a per-sequence block table, OS-style. Near-zero fragmentation, copy-on-write sharing for beam/parallel sampling. Slot: kv-allocator + attn-kernel (block-table-aware). Gain: the paper reports 2-4x throughput over FasterTransformer/Orca at the same latency, with KV waste under 4%. Quality: lossless. Maturity: universal (vLLM, SGLang, TRT-LLM, llama.cpp uses a unified cells model). Src: [arXiv 2309.06180](https://arxiv.org/abs/2309.06180), [vllm repo](https://github.com/vllm-project/vllm).
- **vAttention** (May 2024, ASPLOS'25). What: keeps the KV *virtually contiguous* using CUDA VMM APIs (cuMemMap/cuMemCreate) and maps physical pages on demand, so unmodified non-paged kernels (FlashAttention, FA3) work. Slot: kv-allocator. Pre: CUDA driver VMM. The 2 MB default page granularity is large; the paper patches the driver for 64 KB pages. Gain: up to about 1.97x faster prefill than paged kernels at the time, and it removes block-table indirection from kernels. Quality: lossless. Maturity: research plus Microsoft repo. Src: [arXiv 2405.04437](https://arxiv.org/abs/2405.04437), [microsoft/vattention](https://github.com/microsoft/vattention).
- **Jenga / heterogeneous allocation** (Mar 2025). What: an allocator for models whose layers have different KV shapes (sliding-window, cross-attention, Mamba state, vision embeddings). Uses an LCM page size and per-layer-type eviction. This is the idea behind vLLM's Hybrid Memory Allocator. Slot: kv-allocator. Src: [arXiv 2503.18292](https://arxiv.org/abs/2503.18292).
- **vLLM Hybrid Memory Allocator (HMA) / hybrid KV cache manager** [V]. Manages hybrid GPU memory (full attention + sliding window + Mamba) in one instance. Offloading connectors written for uniform caches either skip offloading or require disabling HMA. llm-d is extending HMA to tiered CPU/storage offload. Slot: kv-allocator. Src: [llm-d blog](https://llm-d.ai/blog/serving-hybrid-models-at-scale-in-llm-d). Some models need `--disable-hybrid-kv-cache-manager` with the native offload backend: [Vultr ROCm guide](https://docs.vultr.com/inference-cookbook/rocm/optimization/kv-cache-offloading).
- **Unified KV buffer vs per-sequence KV**. llama.cpp uses one unified KV "cells" buffer shared by all slots (`-np` parallel slots split `-c`), unless `--kv-unified` is off. vLLM/SGLang use a global block pool. Per-sequence contiguous buffers (HF `DynamicCache`, ExLlama) waste memory at max length. Slot: kv-allocator. Src: [llama-server man page](https://manpages.debian.org/unstable/llama.cpp-tools/llama-server.1.en.html).
- **KV defragmentation**. Contiguous-cell engines (llama.cpp's former `--defrag-thold`) need periodic compaction copies. Paged engines avoid it, at the cost of an indirection in kernels. vAttention avoids both. Slot: kv-allocator. Src: [llama-server man page](https://manpages.debian.org/unstable/llama.cpp-tools/llama-server.1.en.html); [vAttention](https://arxiv.org/abs/2405.04437).

**Prefix reuse**
- **RadixAttention (SGLang)** (Dec 2023, NeurIPS'24). What: a radix tree over token sequences mapping to KV pages, with LRU eviction of leaves and cache-aware scheduling (longest-prefix-first). Slot: prefix-cache + scheduler. Gain: the paper reports up to 6.4x throughput on agent and few-shot workloads. Quality: lossless. Maturity: production. Src: [arXiv 2312.07104](https://arxiv.org/abs/2312.07104), [sglang](https://github.com/sgl-project/sglang).
- **Automatic Prefix Caching (vLLM APC)** [V]. Hash-chained full blocks (hash of parent plus tokens) give O(1) lookup, with LRU free-queue eviction. For Mamba/hybrid models an `align` mode stores SSM state only at block boundaries. Hits resume only at block boundaries, and block size is forced to match the Mamba page (one report: 528-token blocks, so 0% hits for shorter prompts). Slot: prefix-cache. Src: [vLLM APC docs](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching.html), [vllm issue #40696](https://github.com/vllm-project/vllm/issues/40696).
- **Prompt Cache (modular attention reuse)** (Nov 2023, MLSys'24). Precomputes KV for reusable prompt modules at fixed positions using a schema. Slot: prefix-cache. Src: [arXiv 2311.04934](https://arxiv.org/abs/2311.04934).
- **CacheBlend** (May 2024, EuroSys'25). Reuses KV of *non-prefix* chunks (RAG documents) and selectively recomputes about 10-20% of tokens to fix cross-attention. Integrated in LMCache. Slot: prefix-cache. Quality: near full-prefill on RAG QA per the paper. Src: [arXiv 2405.16444](https://arxiv.org/abs/2405.16444).
- **KVLink** (Feb 2025). Precomputes document KV independently and fine-tunes link tokens to restore cross-document attention. Slot: prefix-cache + model-arch (light fine-tuning). Src: [arXiv 2502.16002](https://arxiv.org/abs/2502.16002).
- **Marconi** (Nov 2024, MLSys'25). Prefix caching for hybrid (attention + SSM) models. SSM states cannot be rolled back, so it uses admission and eviction that weigh FLOP savings against memory. Slot: prefix-cache. Src: [arXiv 2411.19379](https://arxiv.org/abs/2411.19379).

**Shared-prefix (cascade) attention kernels**
- **Cascade inference (FlashInfer)** (Feb 2024 blog; FlashInfer paper MLSys'25). Splits attention into a shared-prefix pass (one KV read for the whole batch, using tensor cores in multi-query form) and a per-request suffix pass, merged with log-sum-exp. Slot: attn-kernel. Gain: large decode speedups when many requests share a long system prompt. Pre: a shared prefix across batch. Src: [FlashInfer cascade blog](https://flashinfer.ai/2024/02/02/cascade-inference.html), [arXiv 2501.01005](https://arxiv.org/abs/2501.01005).
- **Hydragen** (Feb 2024). Same decomposition with inter-sequence batching of prefix attention. Src: [arXiv 2402.05099](https://arxiv.org/abs/2402.05099).
- **ChunkAttention** (Feb 2024). A prefix-tree KV with a two-phase partition kernel. Src: [arXiv 2402.15220](https://arxiv.org/abs/2402.15220).
- **RelayAttention** (Feb 2024). Reads system-prompt KV once per batch. Src: [arXiv 2402.14808](https://arxiv.org/abs/2402.14808).

**Sliding window and hybrid-state caching**
- **Sliding-window KV ring buffers** (Mistral 7B, Oct 2023; Gemma 2/3 and gpt-oss interleave local and global layers). A local layer keeps only the last W tokens in a rolling buffer, so memory is O(W) for those layers. Slot: kv-allocator. Pre: the model is trained with SWA. Src: [Mistral arXiv 2310.06825](https://arxiv.org/abs/2310.06825). vLLM FP8 guidance is to skip quantizing small SWA layers (`--kv-cache-dtype-skip-layers sliding_window`) [V]: [vLLM FP8 KV blog](https://vllm.ai/blog/2026-04-22-fp8-kvcache).
- **Hybrid recurrent-state + KV caching** (Jamba, Qwen3-Next/Qwen3.5 Gated DeltaNet, etc.). Constant-size per-sequence SSM/DeltaNet state plus KV only for the few full-attention layers. Prefix caching requires checkpointing state at block boundaries. vLLM's `--mamba-ssm-cache-dtype` controls state precision: one user report says bf16 state halved state size and raised the hit rate from 51% to 79% [V, single user]. LMCache's multiprocess connector did not yet support Gated DeltaNet models [V]. Slot: kv-allocator + prefix-cache. Src: [Jamba arXiv 2403.19887](https://arxiv.org/abs/2403.19887); [friendli model page](https://friendli.ai/models/Twu31/Qwen3.8-27B-AWQ-INT4-MTP-LowLatency); [LMCache hybrid docs](https://docs.lmcache.ai/mp/hybrid_models.html).

### Inferences
- For an agent-searchable engine, the kv-allocator slot should expose page size as a tunable. Large pages (64-256 tokens) favor kernel efficiency and offload DMA (vLLM 0.12 gained a large offload speedup from contiguous block layout, see section 4). Small pages (16) favor prefix-hit granularity and eviction precision.
- Cascade attention only pays off if the 8 streams share a long system/tool prompt. For independent 32K documents it does nothing.

### Gaps
- No independent 2026 benchmark comparing vAttention against paged kernels on Ada/sm_89 was found.
- The status of upstream vLLM prefix caching for Qwen3-Next specifically could not be confirmed. Only a secondary source says it was open.

## 2. KV quantization

### Takeaway
FP8 KV (2x) is the safe default and is effectively free on throughput in vLLM tests. 4-bit with rotation or outlier handling (Hadamard/TurboQuant-4bit, KIVI-style per-channel K) gives about 3.4x with a 1-4 point accuracy cost. 3-bit and below causes measurable long-context and reasoning loss (about 20 points on a reasoning model in vLLM's TurboQuant study). Naive per-tensor INT4 collapses on RULER. Rotation before quantization is now mainline in llama.cpp (Apr 2026) and fixes most q4_0 KV damage.

### Cited Findings
**Engine-level, verified 2026 evidence**
- **FP8 KV in vLLM** [V] (blog Apr 22 2026). `--kv-cache-dtype fp8`. A Hopper FA3 accumulation-precision regression dropped 128k NIAH from 91% (BF16) to 13%. A two-level FP32 accumulation fix brought it to 89%. MRCR recovery: Llama-3.3-70B 97-98% at 128k, Qwen3-30B-A3B 94-98% at 256k, Qwen3.5-27B matched at 1M. Reasoning lost at most 1-2 points. Llama-3.1-8B at concurrency 8 with about 20k input gained 14.9% throughput. Break-even is about 7k context. Prefill is slower at head_dim 256. Per-tensor scales of 1.0 by default, with per-head scales and LLM-Compressor calibration available. Slot: kv-dtype + attn-kernel. Ada (sm_89) is *not* covered in the post. Src: [vLLM FP8 KV blog](https://vllm.ai/blog/2026-04-22-fp8-kvcache).
- **TurboQuant in vLLM** [V] (study May 11 2026, vLLM 0.20.2, H100). Variants and capacity vs BF16: k8v4 about 2.4x, 4bit-nc up to 3.4x, k3v4-nc/3bit-nc 2.3-3.7x. MRCR on Qwen3-30B-A3B: BF16 45.8, FP8 43.1, 4bit-nc 42.3, 3bit-nc 31.2. Reasoning on Qwen3-30B-Thinking: 4bit-nc about 96% recovery, 3-bit variants about 20 points lower. Throughput is 66-80% of BF16 and latency 10-68% higher, while FP8 matches BF16. Not supported for sliding-window or hybrid models. Recommendation: FP8 by default, 4bit-nc under memory pressure. Src: [vLLM TurboQuant study](https://vllm.ai/blog/turboquant).
- **TurboQuant (paper)** (Apr 2025, ICLR 2026). Random rotation, then a near-optimal scalar quantizer, then a 1-bit QJL residual for unbiased inner products. Claims quality-neutral results at 3.5 bits/channel and marginal loss at 2.5. Src: [arXiv 2504.19874](https://arxiv.org/abs/2504.19874). A community vLLM+Triton port (k3/v2) on an RTX 5090 showed 2.0x token capacity with only a few percent throughput change: [0xSero/turboquant](https://github.com/0xSero/turboquant) (unofficial).
- **QJL** (Jun 2024). 1-bit Johnson-Lindenstrauss sign sketch of keys with an unbiased inner-product estimator and no per-block constants. Src: [arXiv 2406.03482](https://arxiv.org/abs/2406.03482). **PolarQuant** (Feb 2025, NeurIPS'25). Polar-coordinate key quantization. Src: [arXiv 2502.02617](https://arxiv.org/abs/2502.02617).
- **llama.cpp KV rotation (PR #21038)** [V] (merged Apr 1 2026). Normalized Hadamard rotation of Q/K/V before caching, with output rotated back. Compatible with all existing KV quant types and adds no new types; MLA models are not supported. Results: Qwen3-8B q4_0 KV PPL 7.645 to 7.501 (F16 7.320). gpt-oss-20b AIME25 with q4_0 KV went from 2.0% to 21.7% (F16 37.9%), and q8_0 went from 31.7% to 37.1%. Qwen3.5-9B q4_0 KLD went from 0.0080 to 0.0051. Cost: tg about 0.88-0.93x, pp about 0.97x on CUDA. Slot: kv-dtype. Src: [llama.cpp PR 21038](https://github.com/ggml-org/llama.cpp/pull/21038). A TurboQuant llama.cpp PR was reportedly closed unmerged (Jun 2026) and `turbo3` cache types exist only in forks (secondary sources): [HF model card](https://huggingface.co/majentik/gemma-4-31b-turboquant).
- **llama.cpp KV cache types**. `-ctk/-ctv` f16, bf16, q8_0, q5_1, q5_0, q4_1, q4_0, iq4_nl. V-cache quantization requires flash attention (`-fa`). Src: [llama-server man page](https://manpages.debian.org/unstable/llama.cpp-tools/llama-server.1.en.html).
- **ExLlamaV2 Q4/Q6/Q8 cache** (2024). Grouped quantization with Hadamard rotation; the author's eval shows Q4 close to FP16. An early production use of rotation for KV. Src: [exllamav2 qcache eval](https://github.com/turboderp/exllamav2/blob/master/doc/qcache_eval.md).
- **INT4 on RULER** [V, single paper]. Naive int4 KV collapses on Qwen3-8B RULER (variable tracking about 0.2 vs 1.00 at fp16). The paper's quaternion multiplicative quantization stays near fp16. Src: [Hurwitz Quaternion MQ, arXiv 2605.27646](https://arxiv.org/pdf/2605.27646).

**Academic KV quantizers**
- **KIVI** (Feb 2024, ICML'24). 2-bit asymmetric: **keys per-channel, values per-token**, with a full-precision residual window of recent tokens. Tuning-free. Claims 2.6x less peak memory and 2.35-3.47x throughput on Llama/Mistral with little quality loss. Slot: kv-dtype. Src: [arXiv 2402.02750](https://arxiv.org/abs/2402.02750), [jy-yuan/KIVI](https://github.com/jy-yuan/KIVI).
- **KVQuant** (Jan 2024, NeurIPS'24). Per-channel pre-RoPE key quantization, non-uniform (sensitivity-weighted) datatypes, dense-and-sparse outliers, and attention-sink-aware quantization. Under 0.1 PPL loss at 3-bit and enables 10M context on 8xA100. 3-bit KVQuant scores 14% higher than KIVI on RULER at similar bits [V]. Src: [arXiv 2401.18079](https://arxiv.org/abs/2401.18079).
- **Atom** (Oct 2023, MLSys'24). W4A4 serving with 4-bit KV and mixed-precision outliers. Src: [arXiv 2310.19102](https://arxiv.org/abs/2310.19102).
- **QServe / QoQ** (May 2024, MLSys'25). W4A8KV4 with SmoothAttention (scales keys to tame outliers) and fused KV4 decode kernels. Claims 1.2-3.5x over TRT-LLM on A100/L40S. Src: [arXiv 2405.04532](https://arxiv.org/abs/2405.04532), [mit-han-lab/omniserve](https://github.com/mit-han-lab/omniserve).
- **ZipCache** (May 2024, NeurIPS'24). Channel-separable token-wise quantization, with mixed precision driven by normalized attention-score saliency. Src: [arXiv 2405.14256](https://arxiv.org/abs/2405.14256).
- **GEAR** (Mar 2024). Ultra-low-bit quantization plus a low-rank error approximation plus a sparse outlier matrix. Near-lossless at about 4-bit-equivalent / 2-bit body. Src: [arXiv 2403.05527](https://arxiv.org/abs/2403.05527).
- **MiKV ("No Token Left Behind")** (Feb 2024). Mixed precision: keeps important tokens high-precision and *quantizes instead of evicting* the rest. Src: [arXiv 2402.18096](https://arxiv.org/abs/2402.18096).
- **Coupled Quantization (CQ)** (May 2024, NeurIPS'24). Jointly quantizes multiple channels (vector-style) to exploit inter-channel dependency, down to 1 bit/channel. Src: [arXiv 2405.03917](https://arxiv.org/abs/2405.03917).
- **SKVQ** (May 2024). Sliding-window full-precision recent tokens plus channel reordering and clipped group quant. Src: [arXiv 2405.06219](https://arxiv.org/abs/2405.06219).
- **IntactKV** (Mar 2024). Keeps pivot-token (sink) KV lossless. Src: [arXiv 2403.01241](https://arxiv.org/abs/2403.01241).
- **Rotation-based activation/KV quant: QuaRot** (Apr 2024, NeurIPS'24) uses Hadamard rotations, giving 4-bit KV with small loss. **SpinQuant** (May 2024, ICLR'25) uses learned rotations. Src: [arXiv 2404.00456](https://arxiv.org/abs/2404.00456), [arXiv 2405.16406](https://arxiv.org/abs/2405.16406).
- **KVTuner** (Feb 2025, ICML'25). Sensitivity-aware layer-wise mixed K/V precision (for example K8V4, K4V2 per layer), searched offline. A natural fit for an agent search loop. Src: [arXiv 2502.04420](https://arxiv.org/abs/2502.04420).
- **CommVQ** (Jun 2025, ICML'25). RoPE-commutative vector quantization codebook, giving 2-bit and 1-bit KV. Src: [arXiv 2506.18879](https://arxiv.org/abs/2506.18879).
- **PQCache** (Jul 2024, SIGMOD'25). Product quantization of keys for approximate top-k retrieval, with KV offloaded to CPU. Src: [arXiv 2407.12820](https://arxiv.org/abs/2407.12820).
- **BitDecoding** (Mar 2025). Tensor-core low-bit KV decode kernels with fused dequant layout. Src: [arXiv 2503.18773](https://arxiv.org/abs/2503.18773).
- **WKVQuant** (Feb 2024) [arXiv 2402.12065](https://arxiv.org/abs/2402.12065). **QAQ** (Mar 2024) [arXiv 2403.04643](https://arxiv.org/abs/2403.04643). **TailorKV** (ACL'25) [arXiv 2505.19586](https://arxiv.org/abs/2505.19586). **VidKV** (2025) [arXiv 2503.16257](https://arxiv.org/abs/2503.16257). Source for this group: [Awesome-KV-Cache-Compression](https://github.com/October2001/Awesome-KV-Cache-Compression).
- **Lexico** (Dec 2024). Sparse coding of KV over a universal dictionary. Src: [arXiv 2412.08890](https://arxiv.org/abs/2412.08890).
- **Transform-coding view of KV compression** (Aug 2026). Src: [arXiv 2608.14191](https://arxiv.org/pdf/2608.14191).
- **"More Tokens, Lower Precision"** (Dec 2024). Under a fixed memory budget, keeping more tokens at lower precision beats fewer tokens at full precision (quantization over eviction). Src: [arXiv 2412.12706](https://arxiv.org/abs/2412.12706).

### Inferences
- On a 4090, sm_89 has FP8 (e4m3) tensor cores, so FP8 KV with FP8 attention is hardware-viable. But vLLM's FP8 validation is Hopper/Blackwell-only. The agent must validate the Ada kernel path (FlashInfer or Triton) for both correctness at long context (the FA3 accumulation bug shows silent long-context collapse is possible) and speed.
- Recommended kv-dtype search space: {bf16, fp8-e4m3 (per-tensor and per-head scales), int8/q8_0, Hadamard + q4/int4 (per-channel K, per-token V, KIVI-style residual window), TurboQuant-4bit-nc}, optionally per-layer mixed via KVTuner. Gate every candidate on a long-context retrieval test (RULER/MRCR/NIAH) plus one reasoning test, not perplexity.
- Quantization stacks multiplicatively with eviction (MiKV, "More Tokens, Lower Precision"), so the agent should search a joint (bits x budget) space.

### Gaps
- No Ada/RTX 4090 published accuracy-and-throughput data for FP8 or INT4 KV kernels in vLLM/SGLang was found.
- No NVFP4 KV-cache accuracy data was found (NVFP4 is Blackwell-only anyway, so it is irrelevant to a 4090).

## 3. KV eviction, sparsity and compression (token selection, budgets, merging, low-rank, cross-layer, MLA conversion)

### Takeaway
There are four families. (1) Permanent eviction (H2O, SnapKV, PyramidKV, Ada-KV, KVzip, KVzap, DMS) saves memory but is lossy and fragile on multi-instruction prompts. (2) Query-aware dynamic sparsity (Quest, ShadowKV, MagicPIG, RetrievalAttention, InfiniGen, DSA) keeps all KV but reads only top-k each step, which saves bandwidth rather than memory unless paired with offload. (3) Head-wise hybrids (DuoAttention, RazorAttention) make most heads streaming and save memory with near-lossless quality. (4) Representation changes (low-rank Palu/ThinK, cross-layer CLA/YOCO/MiniCache, MLA conversion) need calibration or fine-tuning. NVIDIA kvpress is the de facto unified testbed (about 35 presses) and doubles as a ready-made slot catalog.

### Cited Findings
**Benchmarks and caveats**
- **kvpress (NVIDIA)** [V]. Library plus HF leaderboard (RULER 4k). Presses (all training-free): Random, Knorm, SnapKV, ExpectedAttention, StreamingLLM, TOVA, ObservedAttention (H2O), QFilter, PyramidKV, LagKV, KeyDiff, NonCausalAttn, LeverageScore, Compactor, CUR, KVzap, FastKVzip, CapPress, DropKV, ThinK, SimLayerKV, DuoAttention, Finch, KVzip, KVgrad, RestoreKV, KVCompose. Wrappers: AdaKV, LUKV, PerLayer, Composed, KeyRerotation, ChunkKV, EntropyGatedChunkKV, ChunkPress, CriticalKV/CriticalAdaKV, Block, Decoding, CompressionRatioDecoding, PrefillDecoding, DMSPress, CAMPress, MergingPress. Decoding-time compression is experimental (DecodingPress: every 512 steps, target 2048). Quantized cache comes via the HF `QuantizedCache`. Src: [NVIDIA/kvpress](https://github.com/NVIDIA/kvpress), [leaderboard](https://huggingface.co/spaces/nvidia/kvpress-leaderboard).
- **The Pitfalls of KV Cache Compression** [V] (Sep 2025, ACL'26). StreamingLLM, SnapKV, TOVA, H2O and K-Norm on Llama3.1-8B and Qwen2.5-14B (IFEval). Certain instructions are effectively ignored under compression, and eviction bias across instructions causes system-prompt leakage. Src: [arXiv 2510.00231](https://arxiv.org/abs/2510.00231).
- **KV Cache Compression, But What Must We Give in Return?** (Jul 2024, EMNLP'24). Benchmark of quantization, eviction, linear-time and hybrid approaches. Src: [arXiv 2407.01527](https://arxiv.org/abs/2407.01527). **SCBench** (Dec 2024). Shared-context, multi-turn evaluation; shows that sub-O(n) memory methods degrade in multi-turn reuse. Src: [arXiv 2412.10319](https://arxiv.org/abs/2412.10319). **Rethinking KV Cache Compression** (Mar 2025). Many methods give smaller end-to-end gains in real engines than claimed. Src: [arXiv 2503.24000](https://arxiv.org/abs/2503.24000). **Ablation/statistical inference for KV compression** (Jul 2026). Src: [arXiv 2607.09683](https://arxiv.org/pdf/2607.09683).
- **Surveys (2026)**: system-aware KV optimization [arXiv 2607.08057](https://arxiv.org/html/2607.08057); KV management, tensor buffer to distributed hierarchy [arXiv 2607.02574](https://arxiv.org/html/2607.02574v1); KV optimization strategies [arXiv 2603.20397](https://arxiv.org/pdf/2603.20397).

**Static and heuristic eviction (memory-saving, permanent)** (slot: kv-select; maturity: research unless noted)
- **StreamingLLM / attention sinks** (Sep 2023, ICLR'24). Keep the first about 4 "sink" tokens plus a recent window, giving infinite-length streaming with stable PPL. It cannot recall mid-context. Shipped in many engines. Src: [arXiv 2309.17453](https://arxiv.org/abs/2309.17453).
- **H2O** (Jun 2023, NeurIPS'23). Heavy hitters by accumulated attention plus recent tokens; reports up to 29x throughput at a 20% budget. Requires attention scores, which conflicts with FlashAttention. Src: [arXiv 2306.14048](https://arxiv.org/abs/2306.14048).
- **Scissorhands** (May 2023, NeurIPS'23). The "persistence of importance" hypothesis, giving up to 5x compression. Src: [arXiv 2305.17118](https://arxiv.org/abs/2305.17118).
- **FastGen** (Oct 2023, ICLR'24). Profiles heads and applies per-head policies (local, special tokens, punctuation, frequency, full). Src: [arXiv 2310.01801](https://arxiv.org/abs/2310.01801).
- **TOVA** (Jan 2024). Evicts the lowest last-query attention, treating transformers as bounded multi-state RNNs. Src: [arXiv 2401.06104](https://arxiv.org/abs/2401.06104).
- **Keyformer** (Mar 2024, MLSys'24). Gumbel-softmax key-token scoring. Src: [arXiv 2403.09054](https://arxiv.org/abs/2403.09054).
- **SnapKV** (Apr 2024, NeurIPS'24). Uses an observation window (last prompt tokens) to vote for important prefix positions per head, with pooling. Prompt-only compression; reports 3.6x decode speed and 8.2x memory efficiency at 16K. The strongest simple baseline. Src: [arXiv 2404.14469](https://arxiv.org/abs/2404.14469).
- **PyramidKV / PyramidInfer** (Jun/May 2024). Larger budgets in lower layers. Src: [arXiv 2406.02069](https://arxiv.org/abs/2406.02069), [arXiv 2405.12532](https://arxiv.org/abs/2405.12532).
- **Ada-KV** (Jul 2024). Head-adaptive budget allocation across heads under a global budget. Src: [arXiv 2407.11550](https://arxiv.org/abs/2407.11550). Related budget allocators: **HeadKV** [arXiv 2410.19258](https://arxiv.org/abs/2410.19258), **CAKE** (ICLR'25) [arXiv 2503.12491](https://arxiv.org/abs/2503.12491), **DynamicKV** [arXiv 2412.14838](https://arxiv.org/abs/2412.14838), **DBudgetKV** [arXiv 2502.16886](https://arxiv.org/abs/2502.16886), **EvolKV** [arXiv 2509.08315](https://arxiv.org/abs/2509.08315), **LAVa** [arXiv 2509.09754](https://arxiv.org/pdf/2509.09754), **SqueezeAttention** (layer-wise) [arXiv 2404.04793](https://arxiv.org/abs/2404.04793), **LUKV** (2026) [arXiv 2602.08585](https://arxiv.org/abs/2602.08585). List source: [Awesome-KV-Cache-Compression](https://github.com/October2001/Awesome-KV-Cache-Compression).
- **K-norm (L2 norm strategy)** (EMNLP'24). Low key norm correlates with high attention, so it is attention-free and FlashAttention-compatible. Src: [arXiv 2406.11430](https://arxiv.org/abs/2406.11430).
- **Q-Filters** (Mar 2025). Projects keys onto the dominant query SVD direction; FlashAttention-compatible. Src: [arXiv 2503.02812](https://arxiv.org/abs/2503.02812). **LagKV** (query-free) [arXiv 2504.04704](https://arxiv.org/abs/2504.04704). **KeyDiff** (NeurIPS'25; key diversity) [arXiv 2504.15364](https://arxiv.org/abs/2504.15364). **CriticalKV** (includes Wo·V norm) [arXiv 2502.03805](https://arxiv.org/abs/2502.03805). **Compactor** (leverage scores) [arXiv 2507.08143](https://arxiv.org/abs/2507.08143). **CUR** [arXiv 2509.15038](https://arxiv.org/abs/2509.15038). **KVCompose** [arXiv 2509.05165](https://arxiv.org/abs/2509.05165). **CapPress** (2026) [arXiv 2604.25975](https://arxiv.org/abs/2604.25975). **Finch** (TACL; dynamic window plus key re-rotation) [TACL](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00716/125280). All listed in [kvpress](https://github.com/NVIDIA/kvpress) [V].
- **Expected Attention** (Oct 2025, NVIDIA). Scores KV by attention expected from *future* queries, modeled from query statistics. Works for prefill and decode. Src: [arXiv 2510.00636](https://arxiv.org/abs/2510.00636) [V via kvpress].
- **KVzip** (May 2025). Query-agnostic: scores KV by how well the model can reconstruct the context from it. Near-lossless at 3-4x and the strongest leaderboard baseline, but requires extra forward passes (about doubled prefill). Src: [arXiv 2505.23416](https://arxiv.org/abs/2505.23416); leaderboard claim per [MarkTechPost](https://www.marktechpost.com/2026/01/15/nvidia-ai-open-sourced-kvzap-a-sota-kv-cache-pruning-method-that-delivers-near-lossless-2x-4x-compression/) [V, secondary].
- **KVzap** (Jan 2026, NVIDIA). A small surrogate predicts KVzip+ scores from hidden states and uses thresholded eviction (DMS-style). Near-lossless 2-4x and fast enough for production. **FastKVzip** (Jan 2026) uses a lightweight gate approximating KVzip. **RestoreKV** (2026) uses LoRA restore tokens plus KVzip pruning. Src: [arXiv 2601.07891](https://arxiv.org/abs/2601.07891), [arXiv 2601.17668](https://arxiv.org/abs/2601.17668), [arXiv 2608.01247](https://arxiv.org/abs/2608.01247) [V via kvpress].
- **Dynamic Memory Compression (DMC)** (Mar 2024, ICML'24) retrofits models to learn append-vs-merge per head (up to about 4x). **Dynamic Memory Sparsification (DMS)** (Jun 2025, "Inference-time hyper-scaling") uses a learned eviction with delayed eviction, about 8x compression after brief retrofitting, and spends the saved memory on more reasoning tokens. Slot: kv-select + model-arch (retrofit). Src: [arXiv 2403.09636](https://arxiv.org/abs/2403.09636), [arXiv 2506.05345](https://arxiv.org/abs/2506.05345).
- **ChunkKV** (Feb 2025). Evicts semantic chunks rather than tokens and reuses indices across layers. Src: [arXiv 2502.00299](https://arxiv.org/abs/2502.00299). **SentenceKV** [arXiv 2504.00970](https://arxiv.org/abs/2504.00970).
- **R-KV** (May 2025). Redundancy-aware compression for long reasoning traces (decode-time). Src: [arXiv 2505.24133](https://arxiv.org/abs/2505.24133). **MorphKV** (ICML'25; constant-size cache for dialogue) [arXiv 2503.00979](https://arxiv.org/abs/2503.00979). **LaCache** (ICML'25; ladder-shaped cache) [arXiv 2507.14204](https://arxiv.org/abs/2507.14204).
- **SepLLM** (Dec 2024). Keeps separator tokens as segment summaries. Src: [arXiv 2412.12094](https://arxiv.org/abs/2412.12094).
- **KV-Compress** (Oct 2024). Variable per-head eviction *inside a paged vLLM cache*, evicting whole blocks per head. Reports up to 8x compression and 5.18x throughput. A rare paged-compatible implementation. Src: [arXiv 2410.00161](https://arxiv.org/abs/2410.00161).
- Other eviction entries (one-liners). **NACL** (ACL'24) [arXiv 2408.03675](https://arxiv.org/abs/2408.03675). **CORM** [arXiv 2404.15949](https://arxiv.org/abs/2404.15949). **A2SF** [arXiv 2407.20485](https://arxiv.org/abs/2407.20485). **LESS** (eviction plus low-rank state) [arXiv 2402.09398](https://arxiv.org/abs/2402.09398). **Locret** (trained retention heads) [arXiv 2410.01805](https://arxiv.org/abs/2410.01805). **InfiniPot** [arXiv 2410.01518](https://arxiv.org/abs/2410.01518). **SimLayerKV** (lazy layers become streaming) [arXiv 2410.13846](https://arxiv.org/abs/2410.13846). **FastKV** (token-selective propagation) [arXiv 2502.01068](https://arxiv.org/abs/2502.01068). **GemFilter** (early-layer selection) [arXiv 2409.17422](https://arxiv.org/abs/2409.17422). **MiniKV** (2-bit plus eviction) [arXiv 2411.18077](https://arxiv.org/abs/2411.18077). **KVCrush** [arXiv 2503.00022](https://arxiv.org/abs/2503.00022). **PruLong** [arXiv 2506.17121](https://arxiv.org/abs/2506.17121). **CAOTE** [arXiv 2504.14051](https://arxiv.org/abs/2504.14051). Source: [Awesome-KV-Cache-Compression](https://github.com/October2001/Awesome-KV-Cache-Compression).

**Head-wise hybrid (retrieval heads full, others streaming)**
- **DuoAttention** (Oct 2024, ICLR'25). Optimization-identified retrieval heads keep full KV and the rest keep sink plus recent. Reports up to 2.55x memory reduction (MHA) / 1.67x (GQA), up to 2.18x decode speed, and 3.3M context on one A100 when combined with quantization. Quality is near full-attention on NIAH/LongBench. Slot: kv-select + attn-kernel (two kernels). Pre: per-model head profiling, which takes hours. Src: [arXiv 2410.10819](https://arxiv.org/abs/2410.10819), [mit-han-lab/duo-attention](https://github.com/mit-han-lab/duo-attention).
- **RazorAttention** (Jul 2024, ICLR'25). Training-free retrieval-head identification plus a compensation token for dropped tokens, giving over 70% KV reduction. Src: [arXiv 2407.15891](https://arxiv.org/abs/2407.15891).
- **Retrieval Head** (Apr 2024). Shows that fewer than 5% of heads do long-context retrieval. Src: [arXiv 2404.15574](https://arxiv.org/abs/2404.15574).
- **LServe** (Feb 2025, MLSys'25). Unifies static streaming heads with dynamic page-level query-aware selection, giving 2.9x prefill and 1.3-2.1x decode over vLLM. Src: [arXiv 2502.14866](https://arxiv.org/abs/2502.14866).

**Query-aware dynamic sparsity (keeps all KV and reads a top-k subset; saves bandwidth)** (slot: attn-kernel + kv-select, often with kv-tier)
- **Quest** (Jun 2024, ICML'24). Per-page min/max key metadata bounds q·k, and only the top-k pages are loaded. Reports up to 7x self-attention speedup at 32K with negligible loss. Does not save memory by itself. Src: [arXiv 2406.10774](https://arxiv.org/abs/2406.10774), [mit-han-lab/Quest](https://github.com/mit-han-lab/Quest).
- **SparQ Attention** (Dec 2023, ICML'24) [arXiv 2312.04985](https://arxiv.org/abs/2312.04985). **Loki** (low-rank key top-k) [arXiv 2406.02542](https://arxiv.org/abs/2406.02542). **Double Sparsity** (label channels) [arXiv 2408.07092](https://arxiv.org/abs/2408.07092). **TidalDecode** [arXiv 2410.05076](https://arxiv.org/abs/2410.05076). **ClusterKV** [arXiv 2412.03213](https://arxiv.org/abs/2412.03213). **Squeezed Attention** [arXiv 2411.09688](https://arxiv.org/abs/2411.09688). **TokenSelect** [arXiv 2411.02886](https://arxiv.org/abs/2411.02886). **Recycled Attention** [arXiv 2411.05787](https://arxiv.org/abs/2411.05787). **RocketKV** (two-stage) [arXiv 2502.14051](https://arxiv.org/abs/2502.14051). **HashEvict** [arXiv 2412.16187](https://arxiv.org/abs/2412.16187). **InfLLM** (training-free block memory) [arXiv 2402.04617](https://arxiv.org/abs/2402.04617). **ArkVale** (NeurIPS'24; page summaries plus recall from CPU) [paper PDF](https://github.com/pku-liang/ArkVale/blob/main/media/arkvale-nips24-paper.pdf). Source: [Awesome-KV-Cache-Compression](https://github.com/October2001/Awesome-KV-Cache-Compression).
- **InfiniGen** (Jun 2024, OSDI'24). Speculates next-layer important tokens using partial query and key products (skewed weights), prefetching only those from CPU memory. Reports up to 3x over prior offload systems. Slot: kv-tier + kv-select. Src: [arXiv 2406.19707](https://arxiv.org/abs/2406.19707).
- **ShadowKV** (Oct 2024, ICML'25). Stores a low-rank pre-RoPE key on GPU, offloads V to CPU, and reconstructs sparse KV on the fly. Reports up to 6x batch and 3.04x throughput on A100 at no accuracy loss on RULER/LongBench/NIAH. Src: [arXiv 2410.21465](https://arxiv.org/abs/2410.21465), [bytedance/ShadowKV](https://github.com/bytedance/ShadowKV).
- **RetrievalAttention** (Sep 2024). ANNS vector index over CPU-resident keys with attention-aware (OOD query) indexing. Claims 128K context for an 8B model on a single RTX 4090 at about 0.188 s/token. **Directly relevant to the 4090 target.** Src: [arXiv 2409.10516](https://arxiv.org/abs/2409.10516).
- **MagicPIG** (Oct 2024, ICLR'25). LSH *sampling* (not top-k) gives unbiased attention estimates, with the hash tables and attention computed on CPU. Reports up to 5x decode throughput on consumer/L40-class GPUs. Src: [arXiv 2410.16179](https://arxiv.org/abs/2410.16179).
- **SpeCache** (Mar 2025). Speculative KV prefetch from CPU using a low-bit GPU copy. Src: [arXiv 2503.16163](https://arxiv.org/abs/2503.16163).
- **HeadInfer** (Feb 2025). Head-wise offload of KV to CPU with only a few heads resident; claims a 4M-token context for Llama-3-8B on a single 24 GB RTX 4090. Src: [arXiv 2502.12574](https://arxiv.org/abs/2502.12574).
- **Model-native sparse attention**: **NSA** (DeepSeek, Feb 2025, ACL'25 best paper) uses compressed, selected and sliding branches and is trained in. [arXiv 2502.11089](https://arxiv.org/abs/2502.11089). **MoBA** (Moonshot, Feb 2025) uses mixture-of-block attention. [arXiv 2502.13189](https://arxiv.org/abs/2502.13189). **DeepSeek Sparse Attention (DSA, V3.2-Exp, Sep 2025)** [V]: an FP8 "lightning indexer" with its own K cache scores tokens and top-k selection feeds sparse MLA. The vLLM FP8 MLA cache is 656 B/token, prefill and decode are handled separately, and kernels come from DeepGEMM and FlashMLA. Src: [vLLM DSA blog](https://vllm.ai/blog/2025-09-29-deepseek-v3-2), [TRT-LLM DSA blog](https://nvidia.github.io/TensorRT-LLM/1.2.1/blogs/tech_blog/blog15_Optimizing_DeepSeek_V32_on_NVIDIA_Blackwell_GPUs.html).

**KV merging**
- **CaM** (ICML'24). Merges to-be-evicted values into retained ones [OpenReview](https://openreview.net/forum?id=LCTmppB165). **D2O** (ICLR'25). Dynamic discriminative layer budgets plus merge-back of evicted tokens [arXiv 2406.13035](https://arxiv.org/abs/2406.13035). **KeepKV** [arXiv 2504.09936](https://arxiv.org/abs/2504.09936). **Model Tells You Where to Merge (KVMerger)** [arXiv 2407.08454](https://arxiv.org/abs/2407.08454). **HOMER** (ICLR'24; hierarchical merging) [arXiv 2404.10308](https://arxiv.org/abs/2404.10308). Slot: kv-select. Source list: [Awesome-KV-Cache-Compression](https://github.com/October2001/Awesome-KV-Cache-Compression).

**Low-rank / channel compression**
- **Palu** (Jul 2024, ICLR'25). Low-rank projection of K/V weights; caches latents and reconstructs on the fly. Reports about 50% KV compression and up to 1.89x attention speedup with quantization. Slot: model-arch (post-training SVD) + attn-kernel. Src: [arXiv 2407.21118](https://arxiv.org/abs/2407.21118).
- **ASVD** (Dec 2023). Activation-aware SVD of weights, including K/V projections, reducing KV 10-30% training-free. Src: [arXiv 2312.05821](https://arxiv.org/abs/2312.05821).
- **Eigen Attention** (Aug 2024, EMNLP Findings'24). Attention in a low-rank eigenbasis, up to 40% KV reduction. Src: [arXiv 2408.05646](https://arxiv.org/abs/2408.05646).
- **ThinK** (Jul 2024, ICLR'25). Prunes key channels by query-driven importance, about 40% key memory. Src: [arXiv 2407.21018](https://arxiv.org/abs/2407.21018).
- **LoRC** [arXiv 2410.03111](https://arxiv.org/abs/2410.03111). **xKV** (cross-layer SVD) [arXiv 2503.18893](https://arxiv.org/abs/2503.18893). **OjaKV** [arXiv 2509.21623](https://arxiv.org/abs/2509.21623). **DepthWeave-KV** (2026; cross-layer residual factorization) [arXiv 2607.06523](https://arxiv.org/pdf/2607.06523). **TPA (Tensor Product Attention)** is an architecture [arXiv 2501.06425](https://arxiv.org/abs/2501.06425).

**Cross-layer KV sharing**
- **CLA** (May 2024). Adjacent layers share KV, giving 2x further reduction over MQA/GQA; requires training. [arXiv 2405.12981](https://arxiv.org/abs/2405.12981). **YOCO** (May 2024, NeurIPS'24). A decoder-decoder that caches global KV once, with self-decoder efficient attention. [arXiv 2405.05254](https://arxiv.org/abs/2405.05254). **LCKV** (ACL'24) [arXiv 2405.10637](https://arxiv.org/abs/2405.10637). **MLKV** [arXiv 2406.09297](https://arxiv.org/abs/2406.09297). **SwiftKV** (Snowflake; later layers' KV computed from an earlier layer, with distillation) [arXiv 2410.03960](https://arxiv.org/abs/2410.03960). - **MiniCache** (May 2024, NeurIPS'24). Training-free merge of adjacent *deep* layers' KV via magnitude/direction (SLERP) with retention of outlier tokens. [arXiv 2405.14366](https://arxiv.org/abs/2405.14366). **KVSharer** (shares *dissimilar* layers, training-free) [arXiv 2410.18517](https://arxiv.org/abs/2410.18517).

**Architecture-level KV reduction and MLA conversion**
- **MQA / GQA** [arXiv 1911.02150](https://arxiv.org/abs/1911.02150), [arXiv 2305.13245](https://arxiv.org/abs/2305.13245). **MLA** (DeepSeek-V2, May 2024) caches a 512-d latent plus a 64-d RoPE key per layer and absorbs up-projections at decode [arXiv 2405.04434](https://arxiv.org/abs/2405.04434).
- **TransMLA** (Feb 2025). Converts GQA models to MLA (same KV size, more expressive) and then compresses further with brief fine-tuning. [arXiv 2502.07864](https://arxiv.org/abs/2502.07864). **MHA2MLA** (Feb 2025, ACL'25). Partial-RoPE plus low-rank joint KV with about 0.3-0.6% of data fine-tuning; reports about 92% KV reduction on Llama2-7B with a small LongBench drop. [arXiv 2502.14837](https://arxiv.org/abs/2502.14837). Slot: model-arch.
- **Infini-attention** (Apr 2024). Compressive memory plus local attention [arXiv 2404.07143](https://arxiv.org/abs/2404.07143).

### Inferences
- The memory-saving families compatible with paged and flash kernels and with large-batch serving are: head-wise (DuoAttention/RazorAttention style, two KV pools), attention-free scorers (K-norm, Q-Filters, KeyDiff, LagKV, KVzap thresholds), and block-granular eviction (KV-Compress). Scorers that need full attention matrices (H2O, TOVA, SnapKV observation window) need an extra partial-attention pass, which is cheap for SnapKV (last 32-64 queries only).
- Dynamic top-k methods (Quest, ShadowKV, RetrievalAttention, MagicPIG) only save VRAM when combined with offload. On PCIe 3.0 this is the only viable form of KV offload for decode (see section 4).
- Eviction quality claims at 4k RULER (kvpress leaderboard) understate damage on multi-instruction, agentic and multi-turn reuse (Pitfalls, SCBench). Any agent search must use a multi-instruction or multi-turn eval in the fitness function or it will over-select aggressive eviction.

### Gaps
- No public head-to-head of DuoAttention vs KVzap vs ShadowKV on the same MoE model at 32K was found.
- Production-engine support for most eviction methods is absent. vLLM and SGLang ship no general eviction press beyond sliding window and model-native DSA (not verified for the latest releases).

## 4. KV offload and tiering (CPU/disk, LMCache, Mooncake, disaggregation, persistence)

### Takeaway
Offload is mature for *prefix reuse* (store-and-reload instead of recompute) and is on by default or one flag away in vLLM (OffloadingConnector), SGLang (HiCache), llama.cpp (`--cache-ram`, slot save/restore) and LMCache. Offload of the *active decode working set* only works with sparse retrieval (InfiniGen/ShadowKV/RetrievalAttention/HeadInfer) or CPU-side attention, because each decode step would otherwise stream the whole KV over the bus.

### Cited Findings
- **vLLM OffloadingConnector** [V] (v0.11.0, blog Jan 8 2026). `--kv-transfer-config` with `kv_connector: OffloadingConnector` and a CPU block count. DMA transfers overlap with GPU compute. Contiguous block layout in 0.12.0 gave a large speedup. Reports about 2-22x TTFT reduction when loading from CPU vs recompute, depending on prompt size. Slot: kv-tier + prefix-cache. Src: [vLLM blog](https://vllm.ai/blog/2026-01-08-kv-offloading-connector), [Dynamo vLLM offloading docs](https://docs.nvidia.com/dynamo/backends/v-llm/kv-cache-offloading).
- **SGLang HiCache** [V] (Sep 2025). L1 GPU / L2 host / L3 distributed storage on a HiRadixTree. Flags include `--hicache-ratio`, `--hicache-size`, `--hicache-write-policy write_through`, page size and I/O backend. Backends: Mooncake, 3FS, NIXL, AIBrix, local file. Self-reported up to 6x throughput and 80% lower TTFT. Src: [LMSYS blog](https://lmsys.org/blog/2025-09-10-sglang-hicache), [best practices](https://docs.sglang.io/docs/advanced_features/hicache_best_practices).
- **llama.cpp `--cache-ram` / `-cram`** [V] (PR #16391, late 2025). A host-RAM prompt cache acting as extra slots. A new request's prefix is matched against cached prompts and swapped into the active context. Capped by MiB (`-cram 8192`, `-1` unlimited, `0` off) and by token count. It is *not* the live KV cache. Src: [llama.cpp PR 16391](https://github.com/ggml-org/llama.cpp/pull/16391).
- **llama.cpp slot save/restore**. `--slot-save-path` plus `POST /slots/{id}?action=save|restore|erase` persists a slot's KV to disk; `--cache-reuse N` reuses KV via shifting for partially matching prompts. Slot: kv-tier (disk) + prefix-cache. Src: [llama-server man page](https://manpages.debian.org/unstable/llama.cpp-tools/llama-server.1.en.html).
- **LMCache**. A KV cache layer (GPU, CPU, local disk, Redis/remote, Mooncake) for vLLM/SGLang with prefix and non-prefix (CacheBlend) reuse and P/D transfer. Gated DeltaNet hybrids are not yet supported in the multiprocess mode [V]. Src: [LMCache repo](https://github.com/LMCache/LMCache), [LMCache hybrid docs](https://docs.lmcache.ai/mp/hybrid_models.html).
- **Mooncake** (Jul 2024, FAST'25 best paper). KVCache-centric disaggregated architecture (Kimi) with a distributed KV store pooling CPU/DRAM/SSD across nodes and a Transfer Engine (RDMA). Src: [arXiv 2407.00079](https://arxiv.org/abs/2407.00079), [kvcache-ai/Mooncake](https://github.com/kvcache-ai/Mooncake).
- **CachedAttention / AttentionStore** (Mar 2024, USENIX ATC'24). Multi-turn KV saved to a DRAM/SSD hierarchy with layer-wise pre-loading and async saving, plus positional-encoding decoupling for truncation. Reports up to 87% lower TTFT. Src: [arXiv 2403.19708](https://arxiv.org/abs/2403.19708).
- **Pensieve** (Dec 2023, EuroSys'25). Stateful multi-turn serving with a GPU-CPU KV cache. Src: [arXiv 2312.05516](https://arxiv.org/abs/2312.05516).
- **CacheGen** (Oct 2023, SIGCOMM'24). Encodes and compresses KV into bitstreams (delta plus arithmetic coding) for network/disk transfer, about 3.5-4.3x smaller. Src: [arXiv 2310.07240](https://arxiv.org/abs/2310.07240).
- **FlexGen** (Mar 2023, ICML'23). LP-searched offloading policy over GPU/CPU/disk for weights, activations and KV, with 4-bit KV compression and CPU-side attention option, for throughput-oriented batch inference. Src: [arXiv 2303.06865](https://arxiv.org/abs/2303.06865).
- **FastDecode / NEO (CPU attention offload)**. These run decode attention on CPU next to the CPU-resident KV, so only q and the output cross PCIe. Src: [FastDecode arXiv 2403.11421](https://arxiv.org/abs/2403.11421), [NEO arXiv 2411.01142](https://arxiv.org/abs/2411.01142).
- **InstInfer** (Sep 2024). Offloads decode attention and KV to computational SSDs. Src: [arXiv 2409.04992](https://arxiv.org/abs/2409.04992).
- **Disaggregation KV transfer**: **DistServe** (OSDI'24) [arXiv 2401.09670](https://arxiv.org/abs/2401.09670), **Splitwise** (ISCA'24) [arXiv 2311.18677](https://arxiv.org/abs/2311.18677), NVIDIA Dynamo KV router and KVBM tracking tier per block [V] [Dynamo HiCache docs](https://docs.nvidia.com/dynamo/latest/knowledge-base/modular-components/backends/sg-lang/hi-cache). Not relevant on a single GPU except as a KV connector API.
- See section 3 for sparse-retrieval offload: InfiniGen, ShadowKV, RetrievalAttention (8B at 128K on a 4090), MagicPIG, HeadInfer (4M tokens on a 4090), PQCache, ArkVale, SpeCache.

### Inferences
- PCIe 3.0 x16 gives about 12-13 GB/s effective (roughly 16 GB/s theoretical). Streaming a dense 24 GB KV per decode step would take about 2 s/token, so dense KV offload during decode is a non-starter on this rig. Offload helps only for (a) prefix persistence (reload a 32K prefix of about 3 GB BF16 in about 0.25 s vs re-prefilling), (b) sparse top-k retrieval reading a few percent of pages per step, or (c) CPU-side attention over DDR4 (about 40-50 GB/s dual-channel, still memory-bound). These bandwidth figures are general hardware knowledge, not sourced this session.
- The KV tier also competes with MoE expert offload for the same PCIe link and DDR4 bandwidth. Any KV prefetch will contend with expert streaming, so the scheduler should treat the bus as a shared budget.

### Gaps
- No measured numbers were found for vLLM or SGLang CPU offload on PCIe 3.0 consumer platforms.

## 5. Long-context techniques (RoPE scaling, chunked prefill, context parallel, sparse prefill, prompt compression, long decode)

### Takeaway
For serving existing models, the relevant levers are: use the model's native or YaRN RoPE config (pos-enc slot, nearly free), chunked prefill (needed to mix 32K prefills with ongoing decodes without stalling), and sparse prefill (MInference/FlexPrefill/XAttention) to cut 32K+ prefill FLOPs. Context/ring parallelism is multi-GPU only. Prompt compression (LLMLingua) is a lossy upstream option.

### Cited Findings
**Position extension (slot: pos-enc)**
- **Position Interpolation (PI)** (Jun 2023). Linearly scales positions and needs about 1000 steps of fine-tuning. [arXiv 2306.15595](https://arxiv.org/abs/2306.15595).
- **NTK-aware / Dynamic NTK scaling** (2023, community). Changes the RoPE base frequency; the dynamic variant scales with current length and is training-free. Described and compared in the YaRN paper [arXiv 2309.00071](https://arxiv.org/abs/2309.00071).
- **YaRN** (Sep 2023, ICLR'24). NTK-by-parts interpolation plus attention temperature, about 10x fewer tokens than PI to fine-tune. Shipped as `rope_scaling: yarn` in Qwen and DeepSeek configs. Static YaRN in engines can hurt short-context quality. [arXiv 2309.00071](https://arxiv.org/abs/2309.00071).
- **LongRoPE** (Feb 2024, ICML'24). Evolutionary search of non-uniform per-dimension rescale factors, reaching 2M context. **LongRoPE2** (Feb 2025) is near-lossless extension with a needle-driven search. [arXiv 2402.13753](https://arxiv.org/abs/2402.13753), [arXiv 2502.20082](https://arxiv.org/abs/2502.20082).
- **Self-Extend / training-free grouped positions** and **Dual Chunk Attention (DCA)** (used by Qwen2.5-1M) are further training-free extension options. Not verified this session.

**Prefill scheduling (slot: scheduler)**
- **Chunked prefill / SARATHI** (Aug 2023) and **Sarathi-Serve** (OSDI'24). Split long prefills into chunks piggybacked with decode batches (stall-free batching), bounding TBT while keeping high throughput. Default in vLLM V1. [arXiv 2308.16369](https://arxiv.org/abs/2308.16369), [arXiv 2403.02310](https://arxiv.org/abs/2403.02310).

**Sparse prefill (slot: attn-kernel)**
- **MInference 1.0** (Jul 2024, NeurIPS'24). Offline per-head pattern assignment (A-shape, vertical-slash, block-sparse) with dynamic index building. Reports up to 10x prefill speedup at 1M on A100 with maintained accuracy. [arXiv 2407.02490](https://arxiv.org/abs/2407.02490), [microsoft/MInference](https://github.com/microsoft/MInference).
- **FlexPrefill** (ICLR'25) [arXiv 2502.20766](https://arxiv.org/abs/2502.20766). **XAttention** (antidiagonal block scoring) [arXiv 2503.16428](https://arxiv.org/abs/2503.16428). **SpargeAttn** [arXiv 2502.18137](https://arxiv.org/abs/2502.18137). **SampleAttention** [arXiv 2406.15486](https://arxiv.org/abs/2406.15486). **CritiPrefill** [arXiv 2409.12490](https://arxiv.org/abs/2409.12490). **LazyLLM** (dynamic token pruning in prefill) [arXiv 2407.14057](https://arxiv.org/abs/2407.14057). **The Sparse Frontier** (2025 trade-off study) [arXiv 2504.17768](https://arxiv.org/abs/2504.17768). Source list: [Awesome-KV-Cache-Compression](https://github.com/October2001/Awesome-KV-Cache-Compression).

**Context and sequence parallelism (multi-GPU; listed for completeness)**
- **Ring Attention** [arXiv 2310.01889](https://arxiv.org/abs/2310.01889), **Striped Attention** [arXiv 2311.09431](https://arxiv.org/abs/2311.09431), **DeepSpeed-Ulysses** [arXiv 2309.14509](https://arxiv.org/abs/2309.14509), **Context Parallelism for long-context inference (Meta)** [arXiv 2411.01783](https://arxiv.org/abs/2411.01783), **LoongServe** (elastic SP) [arXiv 2404.09526](https://arxiv.org/abs/2404.09526).

**Prompt compression (slot: prompt-xform)**
- **LLMLingua** (EMNLP'23; small-LM perplexity token dropping, up to 20x), **LongLLMLingua** (ACL'24; question-aware), **LLMLingua-2** (ACL'24; distilled token classifier, 3-6x faster). [arXiv 2310.05736](https://arxiv.org/abs/2310.05736), [arXiv 2310.06839](https://arxiv.org/abs/2310.06839), [arXiv 2403.12968](https://arxiv.org/abs/2403.12968), [microsoft/LLMLingua](https://github.com/microsoft/LLMLingua). Survey: [arXiv 2410.12388](https://arxiv.org/abs/2410.12388).

**Memory-efficient long-context decode (slot: attn-kernel)**
- **FlashAttention-2** [arXiv 2307.08691](https://arxiv.org/abs/2307.08691). **Flash-Decoding** (split-KV across SMs, essential for small-batch long-context decode). **FlashDecoding++** [arXiv 2311.01282](https://arxiv.org/abs/2311.01282). **FlashInfer** (paged, ragged and cascade kernels; JIT variants) [arXiv 2501.01005](https://arxiv.org/abs/2501.01005). Low-bit KV decode kernels: BitDecoding, QServe (section 2).

### Inferences
- With 8 x 32K streams, prefill of a new 32K stream (O(n^2) attention) collides with decode of the other 7. Chunk size is a key agent-tunable (TBT vs throughput). Sparse prefill helps mainly above about 64K and is less important at 32K.
- RoPE scaling is a model property. The engine's job is a correct implementation of each `rope_scaling` type (linear, dynamic, yarn, longrope, llama3) and caching cos/sin tables.

### Gaps
- No verification this session of Self-Extend, DCA, or the latest (2026) RoPE-extension work.

## 6. Which techniques matter most when KV trades directly against GPU-resident expert weights (24 GB RTX 4090, PCIe 3.0, 8 x 32K)

### Takeaway
KV for 8 x 32K = 262K tokens is the same order as the whole 24 GB card for typical GQA MoE models, so KV bytes/token is the master variable. Priority order: (1) pick or keep model architectures with small KV (MLA, few-KV-head GQA, hybrid linear attention, SWA layers); (2) FP8, then rotated 4-bit KV (2-3.4x); (3) head-wise streaming (DuoAttention/RazorAttention) or learned thresholded eviction (KVzap/DMS) for another 1.5-4x; (4) sparse-retrieval offload (ShadowKV/RetrievalAttention-style) only if VRAM is still short; (5) host-RAM prefix caching for multi-turn reuse. Dense KV offload over PCIe 3.0 should be ruled out for decode.

### Cited Findings
- FP8 KV is 2x capacity with negligible accuracy loss and no throughput cost on Hopper/Blackwell in vLLM; 4-bit TurboQuant is up to 3.4x at 1-4 points and about 20-34% throughput loss; 3-bit loses significantly on long-context and reasoning — [vLLM TurboQuant study](https://vllm.ai/blog/turboquant), [vLLM FP8 blog](https://vllm.ai/blog/2026-04-22-fp8-kvcache).
- Hadamard-rotated q4_0 KV in llama.cpp restores most quality (gpt-oss-20b AIME25 from 2% to 21.7% vs 37.9% F16; Qwen3-8B PPL within 2.5% of F16) at about 7-12% decode cost — [llama.cpp PR 21038](https://github.com/ggml-org/llama.cpp/pull/21038).
- Under KV-memory saturation, BF16 P99 TTFT reached about 17 s on Llama-70B burst load vs about 1.3-1.5 s with FP8, so KV capacity directly drives tail latency — [vLLM TurboQuant study](https://vllm.ai/blog/turboquant).
- Single-4090 long-context precedents: RetrievalAttention (8B, 128K, about 0.19 s/token) [arXiv 2409.10516](https://arxiv.org/abs/2409.10516) and HeadInfer (8B, 4M tokens) [arXiv 2502.12574](https://arxiv.org/abs/2502.12574).
- Eviction methods are fragile for multi-instruction prompts and system-prompt adherence — [Pitfalls, arXiv 2510.00231](https://arxiv.org/abs/2510.00231). Quantization over eviction at equal memory — [arXiv 2412.12706](https://arxiv.org/abs/2412.12706).
- DSA/MLA-style models have very small KV (vLLM FP8 MLA format 656 B/token/layer) — [vLLM DSA blog](https://vllm.ai/blog/2025-09-29-deepseek-v3-2).

### Inferences
Back-of-envelope KV sizing. These are my calculations from public model configs (layers x KV heads x head_dim x 2 (K,V) x bytes); verify the configs:
- **Qwen3-30B-A3B** (48 layers, 4 KV heads, head_dim 128): BF16 about 96 KiB/token, so 262K tokens is about **24 GiB** (the entire card). FP8 is about 12 GiB, rotated 4-bit about 6.5 GiB (with scales), and 4-bit plus 2x head-wise/eviction about 3-3.5 GiB. Each GiB freed holds roughly 1 GiB of expert weights. At about 4.5-bit weights, one Qwen3-30B-A3B expert layer slice (128 experts x 3 x 2048 x 768 params) is about 0.33 GiB, so FP8 to 4-bit KV frees space for roughly 15+ layers' worth of experts.
- **GLM-4.5-Air-class** (46 layers, 8 KV heads, head_dim 128): about 184 KiB/token BF16, about 46 GiB for 262K. Infeasible without at least 4-bit KV plus eviction or sparse offload.
- **Qwen3-Next-80B-A3B-class hybrid** (only 12 of 48 layers are full attention, 2 KV heads, head_dim 256): about 24 KiB/token BF16 (about 6 GiB for 262K) plus a fixed DeltaNet state per stream. Hybrid architectures change the trade-off more than any KV-compression trick.
- **MLA models** (DeepSeek-V2-Lite: 27 layers x 576 dims): about 30 KiB/token BF16, roughly halved with FP8 MLA cache.
- Priority list for the agent's search space on this rig:
  1. `kv-dtype`: FP8 (validate the Ada kernel path at 32K NIAH/RULER) → Hadamard-int4/q4 with per-channel K and a residual window → per-layer mixed precision (KVTuner).
  2. `kv-select`: DuoAttention-style head split (stable, FA-compatible, near-lossless) or KVzap/Expected-Attention thresholds. SnapKV is the cheap baseline. Always pair with sinks. Avoid H2O/TOVA-style decode-time scorers that need full attention matrices.
  3. `kv-allocator`: paged with hybrid/SWA-aware pools; page size as a tunable.
  4. `prefix-cache` + `kv-tier`: radix/hash prefix cache plus a host-RAM tier (64 GB DDR4 can hold about 20 x 32K BF16 prefixes for Qwen3-30B-A3B, or about 80 at 4-bit).
  5. `kv-tier` for active KV: only sparse retrieval (Quest-page metadata on GPU plus CPU pages, ShadowKV low-rank K on GPU, MagicPIG CPU attention). The PCIe budget is shared with expert streaming.
  6. `scheduler`: chunked prefill size; admission control by KV budget vs expert residency (joint optimization).
  7. `model-arch` (offline, optional): MHA2MLA/TransMLA or Palu conversion for models with fat KV.
- The fitness function must include long-context retrieval (RULER or NIAH at 32K), a multi-instruction or system-prompt-adherence check (Pitfalls), and a reasoning check. Throughput alone will drive the agent to over-compress.

### Gaps
- No source directly models the KV-vs-expert-residency trade-off on a single consumer GPU. The sizing above is inference, not measurement.
- No Ada-specific FP8 or INT4 KV kernel performance numbers were found. Whether vLLM's FlashInfer/Triton FP8 KV path on sm_89 has the long-context accumulation issue is unknown.
- Pre-2025 paper figures were recalled from abstracts and not re-fetched this session. Exact numbers should be spot-checked before publication.
