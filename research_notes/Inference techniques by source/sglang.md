# SGLang (sgl-project/sglang) inference optimization techniques — enumeration as of 2026-10-23

Scope: every performance technique found in the SGLang repo at `main` (commit `6a319e7`, 2026-10-23, latest release v0.5.22 of 2026-10-19), its in-tree kernel library (`python/sglang/kernels/` — the former `sgl-kernel/` directory is no longer a top-level dir of the repo; the AOT wheel sources now live at `python/sglang/kernels/aot/`), `sgl-router`, `sgl-model-gateway`, the docs tree, the GitHub release notes v0.5.14–v0.5.22, and the LMSYS blog index 2024–2026. Method: blob-less `git clone --filter=blob:none` + `git ls-tree` of the full tree (11,258 files), targeted `git show` of registries/dispatch code, docs headings/tables, release notes, blog index via the GitHub contents API, and web search for the Muse Spark Open Kernel Challenge.

Link legend used in the table: `sgl:<path>` = `https://github.com/sgl-project/sglang/blob/main/<path>`; `srt/` = `python/sglang/srt/`; `k/` = `python/sglang/kernels/`; `docs/` = `docs/docs/advanced_features/` unless another docs path is given; `REL:vX` = https://github.com/sgl-project/sglang/releases (release notes for that tag); `BLOG:<slug>` = `https://lmsys.org/blog/<slug>`. "Status" gives in-tree presence at main 2026-10-23 plus the release/blog date where one was found. "Claimed gain" is quoted from the release note/blog/source docstring; "n/a" means no number was found in the sources read (the technique is verified to exist, but no gain figure is cited).

## Key question 1: Which inference optimization techniques does SGLang implement (one row per technique)?

### Takeaway
SGLang at main (Oct 2026) is a plugin-structured engine: 20+ attention backends behind a `register_attention_backend` registry, 20 MoE runner backends × 13 all-to-all backends behind `MoeRunnerBackend`/`MoeA2ABackend` enums with a `FusedOpPool`/`PermuteMethodPool`, ~95 quantization scheme files, a unified Rust-core radix tree with 15 HiCache storage backends, 10 speculative-decoding families behind `spec_registry`, three CUDA-graph backends, and megakernel/monokernel plugin contracts (`srt/megakernels/spec.py`, `srt/monokernels/spec.py`) that out-of-tree packages (sgl-nvidia-mega, sgl-amd-mono, Helion Muse Spark megakernels) register into. 212 technique rows are enumerated below.

## Key question 2: What does SGLang use for the five Muse Spark Open Kernel Challenge paths?

### Takeaway
For Muse Spark Open (816B-A42B, GQA + sliding/global hybrid, 256 experts top-8, per-expert post-RMSNorm) SGLang's reference stack on NVIDIA Blackwell is: BF16 projections via `bf16_gemm_dispatch` (cuBLAS/cuBLASLt by default, optional CuTe-DSL SM100 GEMM, Hopper GEMV, FlashInfer split-K / warp-split-K tuned tactics); attention decode via FlashInfer TRT-LLM MHA (XQA) with FP8 E4M3 KV, page 128, fused Triton QK-norm+RoPE+KV-store and CUDA norm+gate; INT4 W4A16 experts only as a GPTQ/AutoRound CPU-AMX path in-tree (GPU W4A16 would go through the Marlin MoE runner); the decode layer composed of JIT split-K/CuTe-DSL router GEMV on a side stream, fused Triton routing, FlashInfer TRT-LLM NVFP4 MoE with `do_finalize=False` plus a CuTe-DSL/Helion/Triton post-expert-norm weighted-sum finalize and layer-boundary fusions under breakable CUDA graphs and DFlash-V2 verification; the prefill layer via LayerNorm sequence parallelism + DeepGEMM MegaMoE (persistent dispatch+GEMM+combine over symmetric memory) and trtllm_mha context attention. Meta's Helion kernels (and Helion verify megakernels in open PR #44668/#44798) are the challenge's stated baseline; the challenge's own problem specs could not be fetched.

### Inferences
- The challenge's "kernel baseline = SGLang's kernels" most plausibly means the production CUDA/CuTe-DSL/Triton/FlashInfer paths above (Helion is opt-in via `SGLANG_FORCE_FUSED_OP_BACKEND=helion`, and the Helion megakernel PR is unmerged), with Meta's Helion numbers (1.03–3.95x) as the published comparison point; a maxbox plugin per problem should therefore pin: `muse_bf16_proj` → `Bf16GemmBackend` + FlashInfer split-K tactic tables; `muse_attention_decode` → `trtllm_mha` (FlashInfer XQA) + fused QK-norm/RoPE/store; `muse_moe_w4a16` → Marlin/`moe_wna16` on GPU or AMX on CPU; `muse_decode_layer` → the composite above (or a megakernel registered through `MegakernelSpec`); `muse_prefill_layer` → LayerNorm-SP + DeepGEMM MegaMoE.
