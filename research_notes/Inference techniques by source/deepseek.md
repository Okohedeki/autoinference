## Key question 1 — Enumerate every inference optimization technique, one row each

### Takeaway
DeepSeek's stack is now a vertically integrated Blackwell/Ascend-950 engine (DeepInfer) sitting on five kernel libraries (FlashMLA, DeepGEMM, DeepEP, TileKernels, DeepSelect) plus a JIT runtime (DeepJIT); Hopper support was dropped from FlashMLA on 2026-09-30 but the Hopper-era kernels remain in git history, and the papers describe a further set of system-level ideas (two-batch overlap, EP/DP decode topology, disk KV cache, MTP speculation, DSA) that transfer as designs. 130 rows follow.

## Key question 2 — DeepInfer's module boundaries (plugin seams)

### Takeaway
DeepInfer is a vLLM-shaped engine with the hot paths pushed into C++ (`csrc/engine`) and into six vendored kernel libraries; the seams a plugin harness can target are the kernel submodules, the TileLang op directory (one file per op, CUDA and Ascend variants side by side), the attention backend class, the EPLB policy, the draft-model runner, the structured-output matcher and the sampler.

### Cited Findings
- Package layout: `deepinfer/{engine, worker, model_executor, structure_output, ve, distributed, hugging_face, npu_ops, entrypoints}`, `csrc/engine` (C++ scheduler, sequence, block manager, MTP varlen, sampling prep, output processing), `deep_cluster` (hardware/topology), `vendor/{DeepEP, DeepEP-Ascend, DeepGEMM, DeepGEMM-Ascend, DeepSelect, FlashMLA}` — [DeepInfer tree](https://api.github.com/repos/deepseek-ai/DeepInfer/git/trees/main?recursive=1)
- Seams by slot:
  - scheduler: `csrc/engine/scheduler.hpp` + `pybind_scheduler.cpp`; `engine/llm_engine.py`; `flops_estimator.hpp`, `worker/decode_perf_cache.py` (cost models) — [DI tree]
  - kv-allocator / kv-tier: `csrc/engine/block_manager.hpp`, `worker/cache_engine.py`, `input_metadata/block_load_plan.*`, TileLang `load_paged_kv_cache` / `store_kv_cache` / `state_cache` — [DI tree]
  - attn-prefill / attn-decode / kv-select: `model_executor/layers/attention_backend.py`; `models/v4_modules/{attn, mla_attn, index_attn, compress, yoco, cross_layer}.py`; FlashMLA submodule; DeepSelect top-k — [DI tree]
  - moe-gpu / placement: `models/v4_modules/moe.py`; DeepEP + DeepGEMM (Mega MoE) submodules; `model_executor/eplb/{policy,shuffle}.py` — [DI tree], [DI-QA]
  - spec: `models/mtp/dflash.py`, `worker/dflash_cuda_graph_runner.py`, `layers/mtp_info_pool.py`, `csrc/engine/mtp_varlen.hpp`, TileLang `schedule_mtp_varlen` — [DI tree]
  - sampler: `layers/sampler.py`, `sampler_utils.py`, `csrc/engine/prepare_sample.cpp`, TileLang `fused_sample`/`random_sampling`/`sum_smaller_probs`; DeepSelect — [DI tree]
  - structured output: `structure_output/{compiler, matcher, mask, so_matcher_builder}.py` — [DI tree]
  - executor: `worker/{worker, model_runner, cuda_graph_runner, runtime_config}.py`; `csrc/graph_timer` — [DI tree]
  - parallelism: `model_executor/parallel_utils/{parallel_state, communication_op, cp, nccl_memory, userbuffer}.py`, `distributed/shm_broadcast.py` — [DI tree]

## Key question 3 — What transfers to a single RTX 4090 (sm_89) with CPU expert offload

### Takeaway
sm_89 has FP8 (E4M3) tensor cores but no TMA/WGMMA, no FP4, no NVLink and 24 GB HBM, so the transferable set is the algorithmic layer (MLA-MQA absorption, fine-grained FP8 with two-level accumulation, FP8/FP4 KV layouts, DSA indexer + DeepSelect-style top-k, MTP/DSpark confidence-scheduled speculation, EPLB-style hot-expert placement, zero-overhead async scheduling, grouped-masked GEMM for CUDA graphs, SWA bounded replay / YOCO-style prefill truncation, tiered prefix KV) rather than the Hopper/Blackwell kernels themselves.

### Cited Findings
- Ampere/Ada-era hardware limits are acknowledged by DeepSeek themselves: DeepEP v1 supports SM80 "intranode only" and requires SM90 PTX for the full feature set — [DeepEP v1.2.1](https://github.com/deepseek-ai/DeepEP/blob/v1.2.1/README.md); DeepGEMM requires SM90/SM100 — [DeepGEMM](https://github.com/deepseek-ai/DeepGEMM); FlashMLA current main requires SM100/SM103 — [FlashMLA](https://github.com/deepseek-ai/FlashMLA).
- DeepSeek cites KTransformers running full V3 at ~20 TPS on a ~$10k server with a consumer GPU as the reference point for CPU/GPU hybrid MoE — [ISCA §2.2](https://arxiv.org/abs/2505.09343).
- MLA cuts KV to 70 KB/token (BF16), FP8 formats to 528–656 B/token and FP4 to 288 B/token — [ISCA], [FlashMLA].
- MTP speculative decoding gives 1.8× TPS at 85–90% acceptance — [V3 §5.4.3](https://arxiv.org/abs/2412.19437); DSpark's variable-length verification adds +4–11% at high concurrency and −1.5% at low — [DI-QA].
- DSA reduces core attention to O(Lk) with k=2048 (V3.2) or top-k 512 (V4); DeepSelect top-k is a pure-bandwidth kernel 2–20× faster than torch.topk — [V3.2 paper](https://arxiv.org/abs/2512.02556), [DeepSelect](https://github.com/deepseek-ai/DeepSelect).
- Prefix KV on disk hit 56.3% of input tokens in production; SWA bounded replay makes the persisted footprint 1/8 and halves decoder prefill — [OV], [DI-QA], [V41].

### Inferences (transfer list for maxbox, slot in brackets)
1. [attn-decode] MLA absorption / MQA-mode decode (row 110) — pure algebra; implement over any FlashAttention-class kernel for sm_89; the 4090's ~1 TB/s makes the 3000 GB/s FlashMLA figure a ceiling not a requirement.
2. [kv-dtype] FP8 KV page layouts with per-128 or per-32 scales and FP4 E2M1 + per-16 E4M3 (rows 52–53, 20–22) — software dequant in the attention kernel; FP4 arithmetic is not native on sm_89 but storage format is.
3. [kv-select] DSA lightning indexer + top-k selection (rows 86, 106, 131–132) — the indexer is a small FP8 GEMM (sm_89 has FP8 mma) and top-k is bandwidth-bound; cuts long-context attention reads, which is the binding constraint on a 24 GB card.
4. [linear-gpu, quant-recipe] FP8 E4M3 GEMM with 1×128/128×128 scaling and promotion to FP32 every 128 K-elements (rows 75–76, 111–112) — sm_89 FP8 mma.sync lacks TMA/WGMMA but the scaling scheme and accumulation fix port directly (needed because Ada FP8 accumulators have the same limited precision concern).
5. [moe-gpu] Grouped masked GEMM under CUDA graphs (row 79) for the GPU-resident expert subset; grouped contiguous for prefill (row 78).
6. [expert-cache, placement] EPLB logic (rows 95–97, 9) reinterpreted as hot-expert residency: moving-average load → which experts live in the 24 GB GPU vs CPU DRAM; rebalance windows (100/1,000 steps) are directly reusable.
7. [spec] MTP head + DSpark confidence-scheduled variable-length verification (rows 10–11, 117) — with CPU experts, verifying k tokens per step amortizes one CPU weight sweep over k tokens, so speculation is worth more here than on H800s; the GPU-side varlen scheduler keeps the CPU free.
8. [scheduler] Zero-overhead async scheduler (schedule N+1 / post-process N−1 overlapped with forward N) (row 2) and quadratic chunk-cost model (row 3) — host-side, hardware-agnostic.
9. [offload-scheduler, moe-cpu] Two-micro-batch overlap and hook-based "issue then free SMs" pattern (rows 58, 118–119) reinterpreted as overlapping GPU attention of micro-batch A with CPU expert compute of micro-batch B; the profile-data traces are the template.
10. [kv-tier] Tiered prefix cache (HBM → host DRAM → local NVMe) with metadata-only hash-chain matching, async fetch, TTL/LRU GC (rows 38–40, 126) — replace 3FS with a local NVMe store; the 56.3% hit-rate figure motivates it.
11. [attn-prefill, kv-tier] SWA bounded replay and YOCO-style decoder truncation (rows 12–14) — only for models with SWA/encoder-decoder structure (V4.1-Flash), but it is the single biggest prefill saver on a memory-constrained card.
12. [executor] Batch-invariant mode and deterministic GEMM reduction order (rows 15, 93) — host/kernel-ordering discipline, portable.
13. [sampler] Fused top-p via sum-of-smaller-probs and DeepSelect-style radix top-k (rows 19, 107), structured-output token masks (row 17) — portable TileLang/CUDA.
14. [executor] DeepJIT runtime compile with disk cache (row 105) — NVCC path works for sm_89; CUBIN post-hook enables SASS-level tuning on Ada too.
15. [fused-elementwise] TileLang ops (rows 25, 104) — TileLang targets generic CUDA; a `cuda_sm89/` variant directory is the natural port.
- Not transferable as-is: DeepEP (needs NVLink/RDMA; the PCIe "Hybrid-EP" branch is the only relevant fork), Mega MoE (symmetric memory + NVLink), TMA multicast / WGMMA / FFMA-interleaving specifics (sm_90 ISA), FP4 tensor-core GEMMs (sm_100), multi-node EP/DP topologies and load balancers.

### Gaps
- No DeepSeek source quantifies any technique on Ada/sm_89; all 4090 estimates above are inferences. KTransformers' 20 TPS is cited by DeepSeek but not measured by them.
