# Kernel-level and compiler-level techniques for LLM inference: DSLs, compilers, autotuners, kernel libraries (as of 2026-10-23)

Research notes for the maxbox ingestion queue. One row per technique / optimization pass / ready-made kernel. Every row cites the page the fact was read from; rows whose facts could not be confirmed in a fetched source carry **(unverified)** in the maturity column and are listed again after the table. Regime vocabulary: `decode` (small M, memory-bound), `prefill` (large M, compute-bound), `both`, `train` (listed when inference-relevant anyway), `offline` (tooling/quantization time).

## Key question: what kernel/compiler techniques exist, where do they live, and what hardware do they need?

### Takeaway
As of October 2026 the ecosystem splits cleanly along a hardware line: Hopper/Blackwell-only machinery (TMA, wgmma, tcgen05/TMEM, clusters/DSMEM, cluster-launch-control, hardware warp specialization) versus the Ampere/Ada-portable toolbox (cp.async multi-stage pipelining, mma.sync tensor cores, register-level dequant, swizzled shared memory, persistent tile loops, split-K/stream-K, epilogue fusion, CUDA graphs). Triton, Helion, TileLang, CUTLASS 2.x/3.x C++, CuTe DSL (Ampere/Ada warp-level MMA path), cuTile (explicitly Ampere/Ada+Blackwell, Hopper "coming"), FlashInfer (sm_75–sm_121), cuSPARSELt (sm_80–sm_121) and BitBLAS (tested on RTX 4090) all run on sm_89; ThunderKittens, Pallas:Mosaic-GPU, Gluon's wgmma/tcgen05 tutorials, FA3/FA4, Machete, QuTLASS and Triton's warp-specialized/CLC persistent GEMMs do not meaningfully target sm_89.

### Inferences
- For sm_89 the usable "fast path" is: cp.async multi-stage pipelines + mma.sync (fp16/bf16/int8/**fp8**) + register dequant + swizzled smem + persistent tile loop + split-K/stream-K + fused epilogue + CUDA graphs. Everything TMA/wgmma/cluster/CLC/tcgen05-based is a no-op or compile error on Ada, and Helion/Triton explicitly gate those features on CC>=9/10.
- cuTile is the one NVIDIA-first-party tile DSL whose README states Ada support today while Hopper is pending — the inverse of the usual ordering — so it deserves early plugin-porting experiments on 4090-class machines even though it has no autotuner.
- BitBLAS being archived (2026-02-24) and Hidet archived (2026-05-12) means their techniques (Ladder layout propagation, task-mapping) now live on in TileLang and Hexcute respectively; TileLang is the maintained successor for mixed-precision dequant GEMM research on Ada.
- FlashInfer (sm_75–sm_121 coverage, JIT + prebuilt cubins) and the HF kernels hub are the two "ready-made kernel" sources that cover Ada without porting; FA3/FA4, ThunderKittens, Pallas:MGPU, Machete and QuTLASS do not.

### Gaps
- No fetched source gives head-to-head numbers of Triton vs Helion vs TileLang vs CuTe DSL on an RTX 4090; the only cross-DSL number is TileLang's image-only GEMM charts (RTX 4090/A100/H100/MI300X) and Triton's single sample run.
- The exact Ada shared-memory ceiling (per-block opt-in) and register file figures were not retrieved; the Triton tutorial's "will fail on RTX-4090 small shared memory" is the only concrete signal.
- The kernels-community full inventory (58 kernel repos + 68 model repos) was only partially visible (≈40 names across two pages).

## Ranked recommendation: DSLs for an AI agent writing sm_89 (Ada) kernels

1. **Triton (core language, not Gluon)** — Runs on Ada today with its mature `@triton.autotune`, tutorials 01–09 (vector-add, softmax, matmul, layernorm, fused attention, grouped GEMM, persistent matmul naive/persistent variants) all work without TMA; largest body of existing LLM kernels to port from (Liger, Unsloth, fla, FlexAttention codegen, Inductor templates, GemLite). Caveats: no control over smem layout/swizzle; FP8 dot on Ada must be tested (row 47); TMA/WS/CLC variants require CC≥9/10 ([Triton 09](https://triton-lang.org/main/getting-started/tutorials/09-persistent-matmul.html)).
2. **Helion** — Same Ada reach as Triton (it emits Triton) but hands the agent a declarative search space (block sizes, loop orders, l2 groupings, unroll, stages, multi-buffering, indexing mode, pid_type, eviction policies) and a differential-evolution autotuner with AOT-config export — exactly maxbox's "search per machine per objective" model. 58 example kernels cover GEMM/MoE/attention/SSD/norms/losses. Caveats: no tagged release; `tensor_descriptor` and warp specialization are Hopper/Blackwell-only, so on Ada the tuner should prune them ([Helion](https://github.com/pytorch/helion); [examples](https://github.com/pytorch/helion/tree/main/examples)).
3. **TileLang** — Explicit `T.alloc_shared`/`T.alloc_fragment`/`T.Pipelined`/layout control that Triton lacks, SM70–SM120 incl. Windows, parallel multi-GPU autotuning, and the richest ready example zoo for quantized decode (dequantize_gemm, gemm_int4, gemm_fp8, bitnet-1.58b, gemv, flash_decoding, MLA, GDN/KDA). RTX 4090 appears in its GEMM benchmark charts. Caveats: TVM dependency and compile times; license not visible on the fetched page; many 2026 features (TMA stores, automatic WS, cluster copy) are Hopper+ ([TileLang](https://github.com/tile-ai/tilelang); [examples](https://github.com/tile-ai/tilelang/tree/main/examples)).
4. **CuTe DSL (CUTLASS 4.x Python)** — First-party, documented "Ampere and Ada: warp-level MMA" path, full control of layouts/swizzles/copy and MMA atoms, JIT from Python, and it is what FA4 is written in; best for squeezing the last 10% out of mma.sync GEMM/attention on Ada. Caveats: Linux-only, the autotuning guide is thin, and the Ada-specific examples could not be enumerated this session ([CuTe DSL overview](https://docs.nvidia.com/cutlass/latest/media/docs/pythonDSL/overview.html)).
5. **cuTile Python** — The only NVIDIA tile DSL stating Ada support while *Hopper* is still pending; Liger already ships a cuTile variant of fused scaled CE. Caveats: CUDA 13.1+/driver r580+, no autotuner, no tagged release, Blackwell-centric roadmap ([cutile-python](https://github.com/NVIDIA/cutile-python)).
6. **CUTLASS 2.x/3.x C++ (via Inductor `max_autotune_gemm_backends=CUTLASS` or direct)** — Ada-specific examples exist (58/64/94 FP8, 47 Stream-K, 24 grouped, 41 FMHA, 45 dual-GEMM) and the Profiler is a built-in autotuner; heavy for an agent to iterate on but the reference for correctness ([CUTLASS examples](https://github.com/NVIDIA/cutlass/tree/main/examples)).
7. **Not recommended for sm_89**: ThunderKittens (SM80 "no longer actively supported", no Ada mention), Gluon's wgmma/tcgen05/TMA tutorials, Pallas:Mosaic-GPU (Hopper/Blackwell only), FA3/FA4, Machete, QuTLASS (sm_100a/120a), MPK (Ada undocumented) — keep them as Hopper/Blackwell plugins only.
