Legend. Regime: `prefill` (compute-bound prompt phase), `decode` (memory-bandwidth-bound token phase), `both`, `load` (model load / cold start), `cluster` (multi-replica / multi-node serving), `memory` (capacity, not speed). Lossless: `yes` = bit-exact or distribution-preserving; `no` = changes outputs; `~` = numerically close / "near-lossless" as claimed by vendor.

## Key question 1: What performance techniques does each remaining engine implement, and where are the plugin seams?

### Takeaway
Across ~35 engines the same ~12 technique families recur (continuous batching, blocked/paged KV, chunked prefill, prefix caching, CUDA graphs, weight-only 4/8-bit, FP8/FP4 KV, speculative decoding, TP/EP/DP, PD disaggregation, KV offload tiers, fused attention/MoE kernels); what differs is which hardware the kernels target and how the engine exposes them (CLI flags, env vars, Python config dataclasses, kernel registries). Several engines in scope were archived or folded in 2025–2026 (ScaleLLM archived 2026-05; IPEX-LLM archived 2026-01-28; JetStream archived 2026-02-01 into tpu-inference; Aphrodite repo README now describes "Sonar", a vLLM-based successor; DeepSpeed-MII last news 2024-01), which matters for maxbox's plugin prioritisation.

## Key question 2: Where are each engine's plugin seams (abstract backend classes, kernel registries, config knobs)?

### Takeaway
Seams fall into four kinds: (a) config dataclasses/CLI flags that select kernels (LMDeploy, TGI, transformers CB, ScaleLLM, candle-vllm); (b) environment-variable surfaces (Ollama, TGI env mirrors); (c) kernel registries meant for other engines to consume (AITER, HF kernels hub, Modular Mojo kernels, DeepSpeed-Kernels); (d) cluster-level routers/KV managers that sit above any engine (Dynamo, LocalAI router, Ray Serve LLM).

### Cited Findings (per-engine seams)
- **LMDeploy**: two engines selected by `TurbomindEngineConfig` / `PytorchEngineConfig`; TurboMind exposes KV slot count and allocation chunk size; PyTorchEngine hosts the Triton kernels and Ascend backend; DeepSeek path plugs FlashMLA/DeepGEMM/DeepEP. — [README](https://github.com/InternLM/lmdeploy/blob/main/README.md); [TurboMind doc](https://lmdeploy.readthedocs.io/en/latest/inference/turbomind.html)
- **TGI**: every launcher flag has an env mirror (`QUANTIZE`, `KV_CACHE_DTYPE`, `SPECULATE`, `CUDA_GRAPHS`, `MAX_BATCH_TOTAL_TOKENS`, `DISABLE_CUSTOM_KERNELS`); quantize enum is the kernel selector (awq/gptq/marlin/eetq/exl2/bnb/fp8/compressed-tensors). — [launcher](https://huggingface.co/docs/text-generation-inference/reference/launcher)
- **transformers**: `ContinuousBatchingConfig` (hardware-centred) vs `GenerationConfig` (model-centred); `attn_implementation` string + `AttentionInterface` registry; `kernels` package pulls `kernels-community/*` builds; `cache_implementation` string; `DistributedConfig(tp_size)`. — [CB doc](https://huggingface.co/docs/transformers/main/en/continuous_batching); [llm_optims](https://huggingface.co/docs/transformers/main/en/llm_optims)
- **DeepSpeed-MII**: `mii.serve(tensor_parallel, replica_num, max_length)`; kernels come from the separate DeepSpeed-Kernels wheel. — [MII README](https://github.com/deepspeedai/DeepSpeed-MII/blob/main/README.md)
- **Ollama**: `envconfig/config.go` is the whole knob surface (`OLLAMA_FLASH_ATTENTION`, `OLLAMA_KV_CACHE_TYPE`, `OLLAMA_NUM_PARALLEL`, `OLLAMA_SCHED_SPREAD`, `OLLAMA_GPU_OVERHEAD`, `OLLAMA_LLM_LIBRARY`, `LLAMA_ARG_FIT*`, `OLLAMA_VULKAN`); runner selection by library name; Go `ml.Backend` interface for the new engine (unverified this run). — [envconfig](https://github.com/ollama/ollama/blob/main/envconfig/config.go)
- **LocalAI**: backend gallery (OCI image per backend) is itself a plugin system; router config for VRAM-aware / prefix-aware routing. — [LocalAI README](https://github.com/mudler/LocalAI/blob/master/README.md)
- **LightLLM**: pure-Python with "token-level KV cache management" explicitly pitched as a research base; launcher `--mode` list selects kernels (unverified). — [README](https://github.com/ModelTC/lightllm/blob/main/README.md)
- **ScaleLLM**: `--cuda_graph_batch_sizes`, chunked-prefill token/seq budgets, prefix cache toggle (archived). — [README](https://github.com/vectorch-ai/ScaleLLM/blob/main/README.md)
- **Modular MAX**: per-model `arch.py` (e.g., `KVCacheStrategy.PAGED`) plus open Mojo kernel library compiled by the MAX graph compiler. — [MAX](https://max.modular.com/)
- **Dynamo**: backend-agnostic (vLLM/SGLang/TRT-LLM) router (`--router-mode`, KV events), KVBM tiers, Planner SLA fields (`ttft`, `itl`), NIXL. — [Dynamo README](https://github.com/ai-dynamo/dynamo/blob/main/README.md)
- **AWS Neuron**: vLLM plugin (`vllm-neuron`) replaces NxDI; Model Runner V2; compile cache local/remote. — [vllm-neuron](https://github.com/vllm-project/vllm-neuron/blob/main/README.md)
- **OpenVINO GenAI**: pipelines (LLMPipeline, ContinuousBatching), device string CPU/GPU/NPU, LoRA adapter API, optimum-cli export flags. — [README](https://github.com/openvinotoolkit/openvino.genai/blob/master/README.md)
- **AITER**: multi-backend kernel registry (Triton/CK/ASM/HIP/FlyDSL/Opus) that vLLM, SGLang, ATOM and JAX call into — the most direct "kernel plugin" seam in this scope. — [AITER](https://github.com/ROCm/aiter/blob/main/README.md)
- **ExecuTorch**: export-time flags (`model.use_kv_cache`, `use_sdpa_with_kv_cache`, `--use_moe_quantized_op`, `use_shared_embedding`), build flags per backend/kernel lib (`EXECUTORCH_BUILD_XNNPACK`, `EXECUTORCH_BUILD_KERNELS_TORCHAO`, `TORCHAO_BUILD_KLEIDIAI`, `EXECUTORCH_BUILD_COREML`). — [ExecuTorch](https://github.com/pytorch/executorch/blob/main/examples/models/llama/README.md)
- **MLX-LM**: CLI flags (`--max-kv-size`, `--prompt-cache-file`, `--prefill-step-size`), `mlx_lm.convert -q`, `mx.distributed`, macOS `iogpu.wired_limit_mb`. — [mlx-lm](https://github.com/ml-explore/mlx-lm/blob/main/README.md)
- **WebLLM**: `prebuiltAppConfig.model_list` (model lib + quant), cache backend selection, worker type. — [WebLLM](https://github.com/mlc-ai/web-llm/blob/main/README.md)
- **mistral.rs**: `--quant`, ISQ topology files, `mistralrs tune`, multi-GPU mode flags; **candle-vllm**: ISQ type, chunk size, prefix cache toggle, KV dtype (FP8/TurboQuant), TP mode. — [mistral.rs](https://github.com/EricLBuehler/mistral.rs/blob/master/README.md); [candle-vllm](https://github.com/EricLBuehler/candle-vllm/blob/master/README.md)
- **Megatron-Core**: engine mode selection (sync/async × direct/coordinator), `--cuda-graph-impl`, parallel sizes. — [Megatron inference](https://github.com/NVIDIA/Megatron-LM/blob/main/examples/inference/README.md)

### Inferences
- For maxbox slot design, env-var surfaces (Ollama) and CLI enums (TGI quantize, LightLLM `--mode`) map 1:1 onto "quant-recipe" / "attn-*" slots with no code injection; kernel registries (AITER, kernels hub) are the only seams that allow wrapping *individual kernels* rather than whole engines.

### Gaps
- Class-level seams (e.g., Ollama `ml.Backend`, LightLLM backend classes, LMDeploy `TurbomindEngineConfig` field list) were not read from source this run.
